# Пайплайн данных и ML

## Подготовка

`ml_experiments/prepare.py` читает сырые `train.csv` и `test.csv` порциями.
Он оставляет успешные валидации (`validation_result == 1`), берёт дату и час
из `tran_date_time`, а номер маршрута — из `ngpt_route`. Затем считает посадки
по `route × date × hour` и дополняет отсутствующие часы нулями, включая
маршрут 5. Входные файлы, период и выходной CSV задаются аргументами CLI;
подготовленный файл хранится в `untracked/data/`. Его значения сверены с
разметкой из архива: совпали все 72 960 часов января–октября 2025.

## Обучение и проверка

`ml_experiments/evaluate.py` проверяет двухмесячные прогнозы на трёх
последовательных окнах: май–июнь, июль–август, сентябрь–октябрь. Для каждого
окна модель видит только предыдущие даты. Метрика —
`WAPE-score = max(0, 1 − Σ|y − ŷ| / Σy)` по полной почасовой сетке.
Сравниваются сезонные медианы и LightGBM; `evaluate_more.py` дополнительно
проверяет другие настройки LightGBM и CatBoost. Признаки моделей — маршрут,
час и календарные признаки, известные на весь горизонт прогноза. Для 2004–2026
они берутся из сохранённых CSV [isDayOff](../../tools/calendar/README.md),
включая переносы выходных и сокращённые дни. Для годов без CSV используются
обычные выходные и фиксированные государственные праздники РФ без переносов.
`is_weekend` в модели означает нерабочий день по календарю, даже если это будний
день; `is_short_day` отдельно отмечает сокращённый рабочий день.

Пример подготовки календаря для обучения и проверки из корня репозитория:

```bash
python tools/calendar/fetch_isdayoff.py 2025 2026 2027 --output-dir untracked/calendar
```

По умолчанию ML читает `untracked/calendar/`; другой путь задаётся переменной
`CALENDAR_DIR`. Для воспроизводимого эксперимента сохраняйте использованные CSV
рядом с артефактами модели.

`forecast.py` обучается на январе–октябре и строит прогноз на ноябрь–декабрь:
70% LightGBM MAE, 10% LightGBM Poisson и 20% медиана по тому же маршруту,
дню недели и часу за последние 12 недель. Он сохраняет `submission.csv`,
модели и сезонный профиль в `untracked/data/`. `predict_saved.py` воспроизводит
прогноз из сохранённых артефактов без переобучения.
Backend содержит собственный код инференса и снимок артефактов в `backend/ml/`;
изменения в `ml_experiments/` не меняют работающий API без явного обновления
backend и пересборки образа.

## Производительность

Модели загружаются один раз на процесс через `SavedPredictor`. Локальный тест
на 2 закреплённых логических CPU и 2 рабочих потоках обработал 400 новых
запросов `маршрут × дата × час` в секунду: p95 — 1,71 мс, RSS после
предрасчёта — 147 МБ. Запрос одного маршрута на месяц (720 часов) занял
64,5 мс. Первая генерация всей двухмесячной сетки занимает около 1,1 с. Backend
строит при запуске настроенный горизонт (по умолчанию год) через пакетный
инференс, сохраняет результаты в PostgreSQL и выполняет широкую агрегацию в БД.
Приведённый здесь замер относится только к ML-инференсу; результаты HTTP API
находятся в [корневом README](../../README.md).

Команды запуска и измеренные результаты: [ml_experiments/RESULTS.md](../../ml_experiments/RESULTS.md).
Формат данных и правила задания: [документация датасета](../data/README.md).
