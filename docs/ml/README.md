# Пайплайн данных и ML

## Подготовка

`ml_experiments/prepare.py` читает сырые `train.csv` и `test.csv` порциями.
Он оставляет успешные валидации (`validation_result == 1`), берёт дату и час
из `tran_date_time`, а номер маршрута — из `ngpt_route`. Затем считает посадки
по `route × date × hour` и дополняет отсутствующие часы нулями, включая
маршрут 5. Входные файлы, период и выходной CSV задаются аргументами CLI;
подготовленный файл хранится в `untracked/data/`. Его значения сверены с
разметкой из архива: совпали все 72 960 часов января–октября 2025.

## Обучение и проверка

`ml_experiments/evaluate.py` проверяет двухмесячные прогнозы на трёх
последовательных окнах: май–июнь, июль–август, сентябрь–октябрь. Для каждого
окна модель видит только предыдущие даты. Метрика —
`WAPE-score = max(0, 1 − Σ|y − ŷ| / Σy)` по полной почасовой сетке.
Сравниваются сезонные медианы и LightGBM; `evaluate_more.py` дополнительно
проверяет другие настройки LightGBM и CatBoost. Признаки моделей — маршрут,
час и календарные признаки, известные на весь горизонт прогноза.

`forecast.py` обучается на январе–октябре и строит прогноз на ноябрь–декабрь:
70% LightGBM MAE, 10% LightGBM Poisson и 20% медиана по тому же маршруту,
дню недели и часу за последние 12 недель. Он сохраняет `submission.csv`,
модели и сезонный профиль в `untracked/data/`. `predict_saved.py` воспроизводит
прогноз из сохранённых артефактов без переобучения.

## Производительность

Для сервиса модели загружаются один раз через `SavedPredictor`. Локальный тест
на 2 закреплённых логических CPU и 2 рабочих потоках обработал 400 новых
запросов `маршрут × дата × час` в секунду: p95 — 1,42 мс, RSS после
предрасчёта — 153 МБ. Запрос одного маршрута на месяц (720 часов) занял
62 мс. Первая генерация
всей двухмесячной сетки занимает около 1,1 с, поэтому её нужно вычислить при
запуске через `SavedPredictor.precompute()` и отвечать на широкие запросы из
готовой таблицы. HTTP, БД и нагрузка всего контейнера пока не проверены;
этот замер подтверждает только запас самого ML-инференса.
