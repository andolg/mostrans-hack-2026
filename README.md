## Фронтенд

Самодостаточный интерактивный фронтенд диспетчерского дашборда. Он показывает реальные линии и остановки московского трамвая из OSM и накладывает воспроизводимый синтетический прогноз загрузки на горизонтах день, месяц и год.

### Быстрый запуск

Через Docker:

```powershell
docker compose up --build
```

Приложение откроется на <http://localhost:8080>. Контейнеру не требуется backend или доступ к Overpass; все прикладные данные уже находятся в `frontend/public/data`.

Для разработки:

```powershell
cd frontend
npm ci
npm run dev
```

Проверки:

```powershell
npm run typecheck
npm run lint
npm run build
```

### Что реализовано

- MapLibre-карта Москвы с OSM-подложкой и обязательной атрибуцией;
- реальные relation-based геометрии направлений маршрутов т2, 6, 17 и 38;
- раскраска сегментов по расчётной загрузке и масштабирование остановок по посадкам;
- горизонты день (15 минут), месяц (1 час), год (1 день);
- фильтр маршрутов, временной слайдер и анимация;
- выбор маршрута/остановки, hover-карточки и ECharts-график P10–P90;
- адаптивная панель параметров;
- TanStack Query, состояния загрузки/ошибки и репозиторный слой;
- production-сборка Vite → nginx и healthcheck;
- автономные Python-утилиты для обновления OSM и mock-прогнозов.

### Данные

В текущей демонстрационной выборке восемь направлений — по две OSM relations на каждый маршрут. В том числе используются relation `1284062` и обратное направление `1343391` для т2. Полная сеть загружается тем же скриптом без `--route-ref`; подробности — в [tools/osm/README.md](tools/osm/README.md).

Файл прогнозов остановок компактен: он хранит устойчивые коэффициенты остановок и связи с маршрутами, а `StaticForecastRepository` соединяет их с временными рядами маршрутов. Это исключает сотни мегабайт дублированных значений и не влияет на API компонентов.

### Ограничения демо

- OSM-подложка использует публичные raster tiles и требует интернет; линии и прогнозы локальны.
- Загрузка — модельная оценка, а не измеренная занятость салона. Валидации отражают посадки; реальная модель потребует реконструкции высадок/OD.
- Сегменты сейчас соответствуют упорядоченным way-членам route relation. Остановки и relation membership сохранены, поэтому нормализатор можно развить до строгих stop-to-stop сегментов без изменения UI-контракта.
