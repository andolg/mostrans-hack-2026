# МосТрам — прогноз посадок на трамвайных маршрутах

Веб-сервис для диспетчера: показывает фактическое и прогнозное число посадок по трамвайным маршрутам Москвы на карте и временной шкале. Прогноз строится для каждого маршрута и часа, затем суммируется по дням или месяцам. Это помогает сравнивать спрос по времени и маршрутам при планировании выпуска и расписания. **Посадки не равны заполненности вагона**: пересадки, высадки и вместимость модель не оценивает.

## Запуск

Нужны Docker Compose и подготовленный файл `untracked/data/hourly_2025_jan_oct.csv`; для подготовки файла — Python 3.12 и `uv`. Исходные `train.csv` и `test.csv` в репозиторий не входят; их берут из [архива организаторов](https://disk.yandex.ru/d/DiFwlfMOauxjBg) и кладут в `untracked/data/dataset/`. Если почасовой файл уже подготовлен, этап с `uv` можно пропустить. Из корня репозитория:

```powershell
cd ml_experiments
uv sync
uv run python prepare.py --input ../untracked/data/dataset/train.csv --input ../untracked/data/dataset/test.csv --output ../untracked/data/hourly_2025_jan_oct.csv --start 2025-01-01 --end 2025-10-31
cd ..
docker compose up --build -d
```

Интерфейс: <http://localhost:8080>; API и Swagger: <http://localhost:8000/docs>; проверка готовности: <http://localhost:8000/health>. `docker compose` запускает PostgreSQL, backend и frontend. Подготовленная история монтируется в backend только для чтения; обученные модели и геометрия карты уже включены в репозиторий. Подложка OSM в браузере требует доступа к интернету. Для просмотра логов: `docker compose logs -f backend`.

Локальная разработка интерфейса при запущенном backend:

```powershell
cd frontend
npm ci
npm run dev
```

Vite откроет <http://localhost:5173> и перенаправит `/api` на `localhost:8000`. Проверки фронтенда: `npm run typecheck`, `npm run lint`, `npm run build`. Проверки backend: `python -m pip install -r backend/requirements.txt pytest httpx` и `python -m pytest -q backend/tests` (Python 3.12).

## Компоненты и возможности

| Компонент | Что делает |
| --- | --- |
| `ml_experiments/` | Готовит почасовую сетку из валидаций, сравнивает модели на временных окнах, обучает ансамбль и создаёт `submission.csv` и артефакты. |
| `backend/` | FastAPI + SQLAlchemy: загружает историю, использует сохранённую модель из `backend/ml/artifacts/`, предрассчитывает 365 дней прогноза и хранит факты и прогнозы в PostgreSQL. Обучение при запуске не выполняется. |
| `frontend/` | React/TypeScript SPA на Vite: карта MapLibre, график ECharts, выбор маршрута, дат и шага времени, скачивание CSV. В Docker приложение раздаёт nginx. |

Поток данных: `train.csv` + `test.csv` → `prepare.py` → почасовая история → обучение и сохранённые модели → backend/PostgreSQL → REST API → интерфейс. Дневные и месячные значения API суммирует из почасовых строк в БД. Факт доступен по **2025-10-31**, начиная с **2025-11-01** сервис показывает прогноз. Прогноз вне годового предрасчёта вычисляется по запросу и сохраняется в БД; версия прогноза зависит от артефактов и календаря. Повторный запуск использует уже сохранённые строки. Подробнее: [архитектура backend](docs/backend/architecture.md), [архитектура frontend](docs/frontend/architecture.md).

API принимает `from` включительно, `to` исключительно, необязательный `route` и `group_by=hour|day|month`. Время задаётся в календаре датасета без часового смещения. При отсутствии `route` возвращаются ряды всех поддерживаемых маршрутов. Факт и прогноз помечаются `actual`/`forecast`, в том числе при пересечении их границы.

```http
GET /api/boardings?from=2025-11-01T00:00&to=2025-12-01T00:00&route=17&group_by=day
GET /api/boardings/export?from=2025-11-01T00:00&to=2025-12-01T00:00&route=17&group_by=day
GET /api/metadata
GET /health
```

`/api/boardings/export` отдаёт CSV с теми же параметрами и источником каждой строки. В интерфейсе маршрут выбирается на карте или в панели, временной срез — графиком или слайдером. Цвет линии показывает относительный уровень посадок на **этом маршруте** за выбранный период; остановки служат географическими ориентирами и не имеют чисел посадок. Локальная геометрия доступна и без Overpass во время работы приложения.

## Данные и модель

| Источник | Использование |
| --- | --- |
| [Датасет организаторов](https://disk.yandex.ru/d/DiFwlfMOauxjBg) | `train.csv` (январь–август 2025) и `test.csv` (сентябрь–октябрь 2025): успешная валидация `validation_result == 1` считается одной посадкой. `tran_date_time` задаёт дату и час, `ngpt_route` — маршрут. |
| [isDayOff](https://www.isdayoff.ru/docs/) | Сохранённый календарь РФ за 2025–2026 годы: выходные, праздники, перенесённые и сокращённые дни как признаки модели. Для годов без CSV используются обычные выходные и фиксированные праздники без переносов. |
| [OpenStreetMap через Overpass](https://wiki.openstreetmap.org/wiki/Overpass_API) | Линии маршрутов и точки остановок для карты; локальные GeoJSON лежат в `frontend/public/data/osm/`. Данные © OpenStreetMap contributors, ODbL 1.0. Геометрия **не участвует** в прогнозе. |

`prepare.py` читает большие CSV порциями, извлекает номер трамвайного маршрута, считает успешные валидации по `route × date × hour` и дополняет отсутствующие часы нулями. Итоговая история содержит 72 960 часов для маршрутов `1, 5, 7, 11, 12, 17, 25, 26, 28, 50`; все значения были сверены с почасовой разметкой архива. Маршрут 5 есть в сетке, но успешных валидаций в истории нет, поэтому его прогноз принудительно равен нулю. `place_id` в данных обозначает площадку/депо, а не остановку: достоверной привязки посадок к остановкам нет.

Сохранённый ансамбль: **70% LightGBM с MAE, 10% LightGBM с Poisson, 20% медиана** того же маршрута, дня недели и часа за последние 12 недель. Деревья используют маршрут, час, день недели, месяц, день и неделю года, признаки выходного/праздника/сокращённого дня, лета и начала учебного года. Для будущих дат нужны только известные заранее календарные признаки; будущие валидации модель не читает. Результат округляется до неотрицательного целого числа.

В трёх проверках с обучением только на датах **до** прогнозируемого двухмесячного окна ансамбль получил WAPE-score **0,82127** (май–июнь), **0,83122** (июль–август) и **0,81811** (сентябрь–октябрь). `WAPE-score = max(0, 1 − Σ|y − ŷ| / Σy)`; больше — лучше. Сравнение моделей и влияние календаря описаны в [результатах экспериментов](ml_experiments/RESULTS.md). Для скрытых ноября–декабря 2025 фактический score неизвестен; baseline организаторов около 0,48 относится к другому периоду и напрямую с этими проверками не сравнивается.

Чтобы повторить обучение и создать файл для платформы после подготовки истории (из `ml_experiments/`):

```powershell
$env:CALENDAR_DIR = "../backend/calendar"
uv run python evaluate.py --data ../untracked/data/hourly_2025_jan_oct.csv --output ../untracked/data/experiments/initial
uv run python forecast.py --data ../untracked/data/hourly_2025_jan_oct.csv --output ../untracked/data/submission.csv --models-dir ../untracked/data/experiments/final
```

`submission.csv` содержит 14 640 строк за ноябрь–декабрь 2025 (`route;date;hour;prediction`). Backend не читает этот файл: после переобучения артефакты из `untracked/data/experiments/final/` нужно перенести в `backend/ml/artifacts/` и пересобрать образ. Для воспроизведения использованного календаря см. [инструкцию](tools/calendar/README.md); детали подготовки и инференса — в [документации ML](docs/ml/README.md).

## Производительность и границы применения

До последнего обновления календаря и артефактов на локальной машине backend с **2 рабочими процессами**, лимитом **2 vCPU / 2 ГБ RAM** и отдельным PostgreSQL обработал два прогона по 1 200 **кэшированных часовых HTTP-запросов**: **373–392 RPS**, **p95 112–239 мс**, память backend около **318 МиБ**. Команда повтора: `python backend/benchmark_http.py --requests 1200 --rps 400 --workers 32`. При отдельном запуске на пустой БД расчёт и запись 87 600 прогнозных часов заняли **7,94 с**; инициализация одного процесса с историей — **11,98 с** без запуска контейнера. ML отдельно показал 400 RPS и p95 1,71 мс на 2 логических CPU; это замер без HTTP и БД. Замеры не покрывают потоковый приём новых валидаций. [Методика и результаты](ml_experiments/RESULTS.md).

Модель проверена на горизонте **следующих двух месяцев** и на перечисленных маршрутах; прогноз на месяц или год в интерфейсе — агрегат почасовых значений, а дальний годовой прогноз остаётся исследовательским. Погода, пробки, события и изменения маршрутной сети сейчас не используются. Для переноса на новые маршруты нужны история валидаций, обновлённая почасовая сетка и переобучение; для новых периодов — актуальный календарь и проверка качества. Следующий шаг после хакатона — добавить эти источники и подтвердить их эффект на отложенных окнах, затем регулярно обновлять факты и проводить нагрузочные замеры полного сервиса.
