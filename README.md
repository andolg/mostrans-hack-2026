# МосТрам — прогноз посадок на трамвайных маршрутах

Документация: [данные](docs/data/README.md) · [ML-пайплайн](docs/ml/README.md) · [архитектура backend](docs/backend/architecture.md) · [архитектура фронтенда](docs/frontend/architecture.md) · [результаты ML-экспериментов](ml_experiments/RESULTS.md).

ML-инференс без HTTP: 400 RPS, p95 1,42 мс на 2 логических CPU. Замеры полного API приведены ниже; подробности ML — в [документации](docs/ml/README.md).

## Структура проекта

Services:
* Frontend: `frontend/`
* Backend: `backend/` (FastAPI, SQLAlchemy, сохранённая ML-модель)
* Database: PostgreSQL

Data and the descriptions are in `untracked/data/`.

Tools in `tools/`:
* `osm/` - loads OSM data for tram lines.

## Backend

Backend отдаёт фактические посадки до **2025-10-31** и прогноз начиная с
**2025-11-01**. При запуске он загружает подготовленную почасовую историю и
рассчитывает прогноз на 365 дней для всех маршрутов. Прогнозы за пределами
предрассчитанного периода создаются по запросу и сохраняются в PostgreSQL.
Код инференса и снимок обученной модели находятся в `backend/ml/` и не
используют `ml_experiments/` при запуске;
обучение модели при запуске не выполняется. Архитектура и ограничения описаны
в [docs/backend/architecture.md](docs/backend/architecture.md).

Нужен подготовленный файл `untracked/data/hourly_2025_jan_oct.csv` из
ML-пайплайна. Артефакты модели уже лежат в `backend/ml/artifacts/` и входят в
образ; сырые CSV сервису не нужны. После переобучения новые артефакты нужно
скопировать в эту папку и пересобрать образ.
Параметры запуска находятся в `backend/settings.json`, календарные признаки —
в `backend/holidays.json`, подключение к БД задаётся `DATABASE_URL`.

```powershell
docker compose up --build -d postgres backend
```

API доступен на <http://localhost:8000/docs>. Основные запросы:

```http
GET /api/boardings?from=2025-11-01T00:00&to=2025-12-01T00:00&route=17&group_by=day
GET /api/boardings/export?from=2025-11-01T00:00&to=2025-12-01T00:00&route=17&group_by=day
GET /api/metadata
GET /health
```

`from` включительно, `to` исключительно; `route` необязателен,
`group_by=hour|day|month`. Даты и часы задаются по календарю датасета без
смещения часового пояса. Нулевые прогнозы тоже сохраняются в кэше.
`/api/boardings/export` скачивает CSV с теми же параметрами и отдельной колонкой
источника (`actual` или `forecast`).

Для локальных проверок нужен Python 3.12:
`python -m pip install -r backend/requirements.txt pytest httpx`, затем
`python -m pytest -q backend/tests`. Нагрузочный тест:
`python backend/benchmark_http.py --requests 1200 --rps 400 --workers 32`.
На локальной машине с Docker backend запущен в **2 рабочих процессах** и
ограничен **2 vCPU и 2 ГБ RAM**; PostgreSQL работает отдельно. В двух прогонах
по 1 200 кэшированных часовых запросов при заданных 400 RPS получено
**373–392 RPS, p95 112–239 мс**; память backend под нагрузкой — около
**318 МиБ**. Замеры не включают приём потоковых данных и зависят от машины.
На пустой БД расчёт и запись годового прогноза (87 600 строк) заняли **7,94 с**;
загрузка модели и полная инициализация одного процесса, включая историю,
заняли **11,98 с**. Это отдельный замер, без времени запуска контейнера.

## Фронтенд

React-приложение показывает число посадок по маршрутам из backend API. На карте используются локальные геометрии OSM; остановки отображаются без числовых данных. Внизу расположен временной ряд выбранного маршрута с отдельными цветами факта и прогноза. Слайдер меняет период, показанный на карте.

### Быстрый запуск

Через Docker:

```powershell
docker compose up --build
```

Приложение откроется на <http://localhost:8080>. nginx перенаправляет `/api/*` в backend. Подложка OSM требует интернет; геометрии трамвайных маршрутов лежат локально.

Для разработки:

```powershell
cd frontend
npm ci
npm run dev
```

Для локальной разработки нужен запущенный backend на `localhost:8000`: Vite перенаправляет туда `/api/*`.

Проверки:

```powershell
npm run typecheck
npm run lint
npm run build
```

### Что реализовано

- MapLibre-карта с OSM-подложкой и атрибуцией;
- выбор маршрута на карте или в панели, диапазона дат и шага `hour|day|month`;
- данные о посадках из `/api/boardings`, экспорт CSV из `/api/boardings/export`;
- цвет каждого маршрута от зелёного (его минимум) до красного (его максимум) по выбранному периоду и шагу;
- график факта и прогноза с выбором интервала по клику, слайдер времени для состояния карты;
- адаптивная тёмная тема, состояния загрузки и ошибок.

### Данные

Геометрию можно обновить скриптами из [tools/osm/README.md](tools/osm/README.md). Если геометрии выбранного маршрута нет, интерфейс сообщает об этом; график и экспорт остаются доступны. Граница факта берётся из `/api/metadata`; период по умолчанию — следующий месяц после `historical_end`. Начало нельзя ставить раньше `historical_start`; конец периода и прогноз за пределами предрасчёта не ограничены интерфейсом.
