# Погода и раздельные веса внешних источников

26 сентября 2026, ветка `feature/weather-factor`. Цель — проверить, помогает ли погода на том же двухмесячном горизонте, что и исходная оценка, и можно ли дать пользователю независимые коэффициенты для погоды и праздников.

## Данные и протокол

- Цель: почасовые посадки `route × date × hour` за январь–октябрь 2025, 72 960 строк. Метрика — `WAPE-score = max(0, 1 - Σ|y-ŷ|/Σy)`; выше лучше.
- Те же три последовательных окна, что в `RESULTS.md`: май–июнь, июль–август, сентябрь–октябрь. Для каждого окна посадки после даты отсечения не используются в обучении.
- Источник погоды — [Open-Meteo Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api), координаты `55.7558, 37.6173`, часовой пояс `Europe/Moscow`. Архив с 2021-01-01 по 2025-10-31 содержит 42 360 часов без пропусков; SHA-256 CSV: `E8377538D80F5AB28935FE1A6E5D0CF4DE90CE4FA20EADC3B81696735360FB3D`.
- В обучении используется наблюдавшаяся погода. В **основной оценке** погода тестового окна неизвестна: вместо неё берётся климатический профиль, построенный только по 2021–2024 годам (среднее по дню года и часу, сглаживание ±7 дней). Это соответствует исходной задаче предсказать сразу следующие два месяца. `evaluate.py` теперь по умолчанию выбирает `--weather-mode climate`.
- 12 погодных признаков: 7 исходных (температура, ощущаемая температура, осадки, дождь, снегопад, снежный покров, ветер) и 5 производных (осадки в предыдущий час, утром и за день; минимум и максимум температуры за день). Погода одна для всех маршрутов; пространственные различия не учитываются.

Исправлен `fold_splitter()` в `evaluate.py`: ранее внутренняя `split()` вызывала саму себя, поэтому обе программы оценки завершались рекурсией. Запуск без погоды после исправления **точно воспроизвёл** три опубликованных результата исходного ансамбля.

## Добавление погоды в исходный ансамбль

Архитектура и коэффициенты исходного ансамбля не менялись: 70% LightGBM MAE, 10% LightGBM Poisson, 20% медиана за 12 недель. Погодные признаки добавляются в оба бустинга. В таблице — WAPE-score по полной почасовой сетке; «все окна» считается по объединённым строкам, а не как среднее трёх чисел.

| Вариант | Май–июнь | Июль–август | Сентябрь–октябрь | Все окна |
| --- | ---: | ---: | ---: | ---: |
| Исходный календарь, без погоды | 0.780869 | 0.829729 | 0.824884 | **0.811846** |
| Все 12 погодных признаков, климатический профиль | 0.794865 | 0.821627 | 0.808108 | 0.807875 |
| Только 4 температурных признака, климатический профиль | 0.790676 | 0.825302 | 0.808587 | 0.807792 |
| Только 7 признаков осадков/снега, климатический профиль | 0.787855 | 0.820937 | 0.810796 | 0.806331 |
| Все 12 признаков, **фактическая погода теста** | 0.798808 | 0.824218 | 0.810289 | 0.810763 |

Ни один проверенный набор погодных признаков не превысил исходную модель по объединённым окнам. Климатический вариант улучшил май–июнь, но ухудшил сентябрь–октябрь. Последняя строка — диагностический «оракул»: фактическая погода, включая полные дневные суммы и экстремумы, не могла быть известна в начале двухмесячного периода; её нельзя считать честным прогнозным результатом. Даже этот вариант не превысил исходную модель по объединённым окнам.

Финальная модель с погодой обучена на январе–октябре 2025. Архив ограничен 31 октября, поэтому прогноз на ноябрь–декабрь целиком использует климатический профиль, а не наблюдения из будущего. Получено 14 640 прогнозов с суммой **11 963 954** против **12 063 819** у исходного файла. Это изменение суммы, не оценка точности: разметки ноября–декабря нет. `predict_saved.py` воспроизвёл новый CSV побайтно (одинаковый SHA-256 `17FB3181B9BE77651EE36679EAAF60A530E399E04E606807A2E5DB774A495F50`). Артефакты находятся в игнорируемой папке `untracked/data/experiments/weather_final/`; backend пока использует прежнюю модель.

## Раздельные компоненты с пользовательскими весами

Проверен ансамбль из трёх независимо обученных вариантов. Ни один отдельный бустинг не видит одновременно погоду и признак праздника:

- `B`: исходные LightGBM и медиана, но без `is_holiday` и погоды (10 входных признаков бустинга).
- `H`: тот же ансамбль с `is_holiday`, но без погоды (11 признаков). Для эксперимента использован `HOLIDAYS` из `models.py`.
- `W`: тот же ансамбль с погодой, но без `is_holiday` (22 признака); в тесте — климатический профиль.

У каждого варианта остаются коэффициенты 70/10/20. После обучения можно менять внешние веса без переобучения:

`ŷ = max(0, round(B + λп × (H - B) + λпог × (W - B)))`.

Однако разность `H-B` появляется не только в праздники: отдельное обучение бустинга меняет прогноз для большинства обычных часов. Для понятного пользователю «веса праздников» проверен также вариант с множителем `I[праздник]` перед `(H-B)`. Он меняет только отмеченные даты.

| Раздельный вариант | Май–июнь | Июль–август | Сентябрь–октябрь | Все окна |
| --- | ---: | ---: | ---: | ---: |
| `B`, оба веса 0 | 0.783994 | 0.824505 | 0.821733 | 0.810131 |
| `H`, вес праздников 1 на **всех** датах, погода 0 | 0.780869 | 0.829729 | 0.824884 | 0.811846 |
| `W`, праздники 0, погода 1 | 0.791689 | 0.827135 | 0.810634 | 0.809433 |
| Вес праздников 1 **только в праздники**, погода 0 | 0.786827 | 0.824505 | 0.821733 | 0.811066 |
| Вес праздников 1 **только в праздники**, погода 0.5 | 0.791292 | 0.832645 | 0.817058 | **0.813327** |

Последняя комбинация — лучшая среди проверенной сетки весов `0, 0.25, 0.5, 1` по объединённым окнам. Прирост к исходному ансамблю составляет **0.001481**, но вес выбран по тем же окнам, на которых измерен результат. На последнем окне он хуже исходного на **0.007826**; это не доказательство улучшения на новых датах. На тесте встречаются лишь три помеченных праздничных дня (1 и 9 мая, 12 июня), поэтому устойчиво подобрать вес праздников здесь нельзя. На этих днях суммарный факт — 332 177 посадок, прогнозы `B` и `H` — примерно 733 911 и 700 406: даже модель с признаком праздника сильно завышает спрос. Все 16 комбинаций для обоих способов применения праздничной поправки сохранены в `untracked/data/experiments/external_weights/weight_scores.csv`.

## Вывод для продукта

Раздельная формула позволяет менять два коэффициента при запросе без повторного обучения; веса стоит применять к почасовым предсказаниям **до** агрегации. Для этого backend понадобится хранить или рассчитывать `B`, `H` и `W` раздельно: текущий кэш содержит только одно итоговое число для часа. Праздничную поправку логичнее ограничить отмеченными днями. Пока нет надёжного основания заменить рабочую модель погодной или назначить ненулевой вес погоде по умолчанию: климатические признаки дают нестабильный эффект, а выбор веса на этих же окнах переоценивает качество.

Для оценки погоды на коротком горизонте нужен архив прогнозов, выпущенных **до** соответствующего часа, например [Open-Meteo Historical Forecast API](https://open-meteo.com/en/docs/historical-forecast-api), и отдельный backtest по времени выпуска. Наблюдавшаяся погода из архивного API проверяет наличие сигнала, но не качество доступного тогда прогноза. Также нужно расширить проверку праздников и согласовать календарь обучения с `backend/holidays.json` перед внедрением весов в API.

```powershell

uv run python evaluate.py --data ../untracked/data/hourly_2025_jan_oct.csv --output ../untracked/data/experiments/weather_baseline
uv run python evaluate.py --data ../untracked/data/hourly_2025_jan_oct.csv --weather ../untracked/data/weather/moscow_hourly.csv --weather-mode climate --output ../untracked/data/experiments/weather_climate
uv run python evaluate.py --data ../untracked/data/hourly_2025_jan_oct.csv --weather ../untracked/data/weather/moscow_hourly.csv --weather-mode climate --weather-columns temperature_2m,apparent_temperature,temperature_day_min,temperature_day_max --output ../untracked/data/experiments/weather_climate_temperature
uv run python evaluate.py --data ../untracked/data/hourly_2025_jan_oct.csv --weather ../untracked/data/weather/moscow_hourly.csv --weather-mode climate --weather-columns precipitation,rain,snowfall,snow_depth,precipitation_prev_hour,precipitation_morning,precipitation_day --output ../untracked/data/experiments/weather_climate_precipitation

uv run python forecast.py --data ../untracked/data/hourly_2025_jan_oct.csv --weather ../untracked/data/weather/moscow_hourly.csv --output ../untracked/data/experiments/weather_final/submission.csv --models-dir ../untracked/data/experiments/weather_final/models

```
